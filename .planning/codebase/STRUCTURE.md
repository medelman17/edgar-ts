## Directory Purposes

**src/**
- Purpose: All TypeScript source code for the library
- Contains: Client facade, type contracts, error taxonomy, and specialized internal modules
- Key files: `client.ts` (public API), `index.ts` (barrel export)

**src/types/**
- Purpose: Define all public API type contracts and internal shared types
- Contains: EdgarClientOptions, RetryOptions, TelemetryOptions, FilingRef, ExhibitRef, DownloadedExhibit, request/retry events
- Key files: `index.ts` (all types exported here)

**src/errors/**
- Purpose: Typed error taxonomy with retryability hints for orchestrator-friendly error handling
- Contains: EdgarError base class, ConfigurationError, ValidationError, TransportError, RateLimitedError, TimeoutError, NotFoundError, ParseError
- Key files: `index.ts` (all error classes exported)

**src/http/**
- Purpose: SEC-compliant HTTP client owning all transport concerns
- Contains: SecHttpClient (not yet implemented) for rate limiting, retry, timeout, header management
- Key files: `index.ts` (stub; SecHttpClient will live here)

**src/discovery/**
- Purpose: Filing discovery service handling SEC endpoint queries and normalization
- Contains: DiscoveryService (not yet implemented) for querying EDGAR by date/form, normalizing, deduplicating, sorting FilingRef records
- Key files: `index.ts` (stub)

**src/exhibits/**
- Purpose: Exhibit parsing, normalization, and contract filtering
- Contains: ExhibitService (not yet implemented) for fetching filing details, extracting exhibits; ContractExhibitFilter for EX-10* matching
- Key files: `index.ts` (stub)

**src/download/**
- Purpose: Raw exhibit byte retrieval with metadata computation
- Contains: DownloadService (not yet implemented) for fetching exhibit bytes, computing size, computing SHA-256 digest
- Key files: `index.ts` (stub)

**src/telemetry/**
- Purpose: Optional observability hooks for request lifecycle events
- Contains: Hook emitters for onRequestStart, onRequestEnd, onRetry events
- Key files: `index.ts` (stub)

**tests/**
- Purpose: Test suite using Vitest with globals enabled
- Contains: Unit tests for EdgarClient and error taxonomy
- Key files: `client.test.ts` (EdgarClient instantiation tests), `errors.test.ts` (error class and retryability tests)

**tests/fixtures/**
- Purpose: Mock responses and test data
- Contains: SEC EDGAR response fixtures for discovery, exhibits, and downloads
- Key files: To be populated during implementation

**docs/**
- Purpose: Planning, specification, and architecture documentation
- Contains: Work breakdown, API contract, architecture specification, error/retry policy, SEC compliance rules, test strategy, data normalization rules
- Key files: See Directory Layout above

**dist/**
- Purpose: Build output (generated by tsdown during `pnpm build`)
- Contains: Dual format builds (ESM and CommonJS) plus type declarations
- Generated: Yes; excluded from git via `.gitignore`

## Key File Locations

**Entry Points:**
- `src/index.ts`: Main barrel export exposing EdgarClient, types, and errors to consumers
- `src/client.ts`: EdgarClient class definition; public API facade
- Build entry: Configured in `tsdown.config.ts` as `src/index.ts`

**Configuration:**
- `tsconfig.json`: TypeScript compiler options (strict mode, isolatedDeclarations, path alias `@/*` → `src/*`)
- `vitest.config.ts`: Vitest config with globals enabled, path alias, coverage targets (80% lines/functions/statements, 75% branches)
- `tsdown.config.ts`: Build configuration for dual format (ESM + CommonJS) with declarations and minification
- `biome.json`: Linter/formatter rules (100-char lines, 2-space indent, double quotes, trailing commas, noExplicitAny error, noParameterAssign error)
- `package.json`: NPM metadata, exports configuration (dual types for import/require), scripts, dependencies

**Core Logic:**
- `src/client.ts`: EdgarClient constructor and method stubs (discoverFilings, listExhibits, listContractExhibits, downloadExhibit)
- `src/types/index.ts`: Type contracts (EdgarClientOptions, FilingRef, ExhibitRef, DownloadedExhibit, RetryOptions, TelemetryOptions)
- `src/errors/index.ts`: Error taxonomy with retryability flags

**Testing:**
- `tests/client.test.ts`: EdgarClient constructor validation tests
- `tests/errors.test.ts`: Error class instantiation and retryability flag tests
- `vitest.config.ts`: Test runner configuration with coverage thresholds

## Naming Conventions

**Files:**
- `*.ts`: TypeScript source (strict mode enforced)
- `*.test.ts`: Vitest test file (naming pattern: mirror src structure but in tests/ directory)
- `index.ts`: Barrel file in every module directory (exports all public symbols from that module)
- `.d.ts`: Type declaration files (generated during build; for manual edits, prefer `.ts` with type annotations)

**Directories:**
- Lowercase, plural for collections: `src/errors/`, `src/types/`, `tests/fixtures/`
- Semantic domain names: `discovery`, `exhibits`, `download`, `http`, `telemetry` (not `utils/`, `helpers/`, etc.)

**Classes:**
- PascalCase: `EdgarClient`, `ConfigurationError`, `TransportError`
- Service/handler classes: Suffix with `Service`: `DiscoveryService`, `ExhibitService`, `DownloadService`
- Filter classes: Suffix with `Filter`: `ContractExhibitFilter`

**Functions/Methods:**
- camelCase: `discoverFilings()`, `listExhibits()`, `listContractExhibits()`, `downloadExhibit()`
- Private methods: No underscore prefix; use `private` keyword in classes

**Types/Interfaces:**
- PascalCase: `FilingRef`, `ExhibitRef`, `DownloadedExhibit`, `EdgarClientOptions`, `RetryOptions`
- Event types: Suffix with `Event`: `RequestStartEvent`, `RequestEndEvent`, `RetryEvent`

**Constants:**
- SCREAMING_SNAKE_CASE: `DEFAULT_MAX_REQUESTS_PER_SECOND`, `DEFAULT_TIMEOUT_MS`

**Variables:**
- camelCase: `userAgent`, `maxRequestsPerSecond`, `timeoutMs`, `retries`

## Where to Add New Code

**New Feature (e.g., new discovery method):**
- Primary code: Add method to `EdgarClient` in `src/client.ts`
- Internal logic: Implement supporting service in appropriate module (e.g., `src/discovery/index.ts`)
- Types: Add type contract to `src/types/index.ts` if public-facing; use local types otherwise
- Tests: Add test file in `tests/` mirroring the structure (e.g., `tests/discovery.test.ts`)
- Exports: Update `src/index.ts` to export new types if public

**New Component/Module (e.g., new filtering strategy):**
- Create new directory under `src/`: `src/filters/` with `index.ts` barrel file
- Implement classes/functions in `src/filters/index.ts` or split across focused files (e.g., `src/filters/contract-filter.ts` + `index.ts` re-export)
- Export from barrel file: `export { ContractExhibitFilter } from "./contract-filter"`
- Define types in `src/types/index.ts` or colocate as needed
- Add tests in `tests/filters.test.ts`

**Utilities/Helpers:**
- Shared validation: `src/validation.ts` (if cross-cutting; otherwise colocate)
- Normalization helpers: `src/normalization.ts` (if cross-cutting; otherwise colocate in domain module)
- No general `src/utils/` directory; keep utilities close to their usage
- Re-export from module barrel files as needed

**Internal Types vs Public Types:**
- Public types: `src/types/index.ts` (exported from main `src/index.ts`)
- Internal/service types: Colocate in module directory (e.g., `src/discovery/types.ts`); not re-exported from main barrel

## Special Directories

**dist/**
- Purpose: Build output directory (all distribution files)
- Generated: Yes (created by `pnpm build` running tsdown)
- Committed: No (excluded via `.gitignore`)
- Contains: Minified ESM/CJS builds + type declarations + source maps
- Structure: Flat at root level (index.mjs, index.cjs, index.d.mts, index.d.cts, source maps)

**.changeset/**
- Purpose: Store changeset files for semantic versioning via changesets CLI
- Generated: Yes (created by `pnpm changeset`)
- Committed: Yes (part of release workflow)
- Contains: Markdown files describing changes per release (format: `[PR-number].[type].md`)

**docs/**
- Purpose: Planning, specification, and architecture reference
- Generated: No (hand-authored)
- Committed: Yes (reference material for implementation)
- Contains: PRD, work breakdown, architecture spec, API contract, data model, error/retry policy, SEC compliance rules

**.claude/, .gemini/, .opencode/**
- Purpose: IDE/orchestrator integration
- Generated: Varies (some files auto-generated by tools)
- Committed: Varies (configuration typically committed, caches ignored)
- Contains: Tool-specific context, hooks, and configuration

**node_modules/**
- Purpose: Installed dependencies
- Generated: Yes (created by `pnpm install`)
- Committed: No (excluded via `.gitignore`)
