Create `src/discovery/normalization.ts` with pure functions for SEC data normalization:

1. **normalizeCik(input: string): string**
   - Strip leading zeros (e.g., "0000320193" → "320193")
   - Validate numeric-only (reject non-digit characters)
   - Validate range: must be ≤ 9999999999 (10-digit max)
   - Zero-pad to 10 digits (e.g., "320193" → "0000320193")
   - Throw ValidationError for invalid input
   - Must be idempotent: normalize(normalize(x)) === normalize(x)

2. **normalizeAccession(input: string): string**
   - Remove all spaces and existing hyphens
   - Validate: exactly 18 digits after cleaning
   - Format as ##########-##-######
   - Throw NormalizationError for invalid format
   - Handle: "0000000000-20-000000", "000000000020000000", "0000000000-20000000"

3. **normalizeFormType(input: string): string**
   - Trim whitespace
   - Uppercase all characters
   - Preserve slash for amendments (e.g., "10-k/a" → "10-K/A")

4. **validateDate(input: string): void**
   - Check format: YYYY-MM-DD via regex
   - Parse and validate via new Date()
   - Throw ValidationError if invalid

Create `src/discovery/deduplication.ts` with deduplication logic:

1. **dedupeAndSort(filings: FilingRef[]): FilingRef[]**
   - Build identity key: `${filing.cik}:${filing.accessionNo}` (both must be normalized)
   - Use Map<string, FilingRef> to track first occurrence of each identity
   - If duplicate found, skip (retain first occurrence only)
   - Convert Map values back to array
   - Stable sort:
     - Primary: filingDate ascending (use localeCompare)
     - Secondary: accessionNo ascending (use localeCompare)
   - Return deduplicated, sorted array

Implementation notes:
- Do NOT normalize inside dedupeAndSort — assume inputs are already normalized
- Use localeCompare for string sorting (ISO 8601 dates sort lexicographically)
- Preserve stable sort: if filingDate and accessionNo match, preserve input order
- No telemetry hooks yet (deferred to Phase 5 integration)

Write tests in `tests/discovery/deduplication.test.ts`:
- Empty array → empty array
- Single filing → single filing
- No duplicates → same order after sort
- Exact duplicates (same CIK + accession) → only first retained
- Different filings, same CIK → sorted by date, then accession
- Same date, different accessions → sorted by accession
- Edge case: 100 filings with 50 duplicates → verify count and order

Use FilingRef type from `@/types`. Export from src/discovery/index.ts.
