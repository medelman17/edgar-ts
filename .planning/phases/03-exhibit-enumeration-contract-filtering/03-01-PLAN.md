Create `src/exhibits/parsing.ts`:
- Implement parseExhibitTableFromHtml(htmlContent: string): RawExhibit[]
- Custom HTML table parsing strategy (NO DOMParser):
  1. Extract table block using regex: /<table[\s\S]*?<\/table>/i
  2. Split table into rows using /<tr[\s\S]*?<\/tr>/gi
  3. For each row: extract cells using /<td[\s\S]*?<\/td>/gi
  4. Clean cell content: strip tags, decode HTML entities (&amp; → &), trim whitespace
  5. Map cells to RawExhibit fields based on position (sequence, description, filename, type)
  6. Extract filename from anchor href if present: /<a[^>]*href="([^"]+)"/ or fall back to text content
- Throw ParseError if no table found or table structure invalid
- Skip header rows (identify via <th> tags or first row heuristic)
- Handle edge cases: missing cells, extra whitespace, nested elements
- Add JSDoc with example EDGAR table structure from research (lines 98-116 in RESEARCH.md)

- Test HTML entities in description (e.g., &amp;, &quot;) → decoded correctly
- Test filename extraction from <a href="..."> tags
- Test whitespace handling (leading/trailing spaces in cells)
- Test header row skipping (rows with <th> tags ignored)

Create `src/exhibits/normalization.ts` with three pure functions mirroring Phase 2 normalization pattern:

**1. normalizeSequence(input: string): string**
- Trim whitespace
- Validate numeric string only: /^\d+$/
- Do NOT remove leading zeros (sequence "001" stays "001" for identity key uniqueness)
- Throw ValidationError with { input } context if non-numeric
- Add JSDoc: "Normalizes exhibit sequence number. Preserves leading zeros for identity uniqueness."

**2. normalizeExhibitType(input: string): string**
- Trim whitespace
- Convert to uppercase
- Normalize separators: replace _ and / with hyphen → "EX_10.1" becomes "EX-10.1"
- Validate against pattern: /^EX-\d+(\.\d+|[A-Z])?$/
- Throw ValidationError with { input, normalized } context if pattern doesn't match
- Add JSDoc: "Normalizes exhibit type. Handles variants: EX_10, EX/10, EX-10 all become EX-10. Supports dotted forms (EX-10.1) and letter suffixes (EX-10A)."

**3. normalizeDescription(input?: string): string | undefined**
- If input is undefined or empty → return undefined
- Trim whitespace
- Return trimmed string if non-empty, otherwise undefined
- No validation needed (descriptions are freeform text)
- Add JSDoc: "Normalizes exhibit description. Converts empty/whitespace-only to undefined."

All functions:
- Explicit return type annotations (isolatedDeclarations requirement)
- Import ValidationError from @/errors
- Follow Phase 2 style: pure functions, no side effects, comprehensive error messages
